# QR Code Credential Download - Implementation Summary

## What Was Created

I've implemented a complete QR code-based credential download system that allows users to download credential files (PKCS#12, PFX, TAR.GZ) by scanning a QR code with their device camera.

## How It Works

### User Flow

1. **Admin initiates browser onboarding**
   - Navigate to credential download page
   - System generates OTP and download token

2. **QR Code is displayed**
   - QR code contains URL with embedded token
   - URL format: `https://trustpoint.example.com/devices/credentials/{id}/qr-download?token={token}&format=PKCS12`

3. **User scans QR code**
   - Opens camera app on mobile device
   - Scans the displayed QR code
   - Browser opens the download URL

4. **Automatic download**
   - System validates the token
   - Generates credential file in requested format
   - File is immediately downloaded to device
   - Token is deleted after successful download

### Technical Flow

```
┌─────────────────┐
│ OTP View        │
│ (browser_       │
│  onboarding.py) │
└────────┬────────┘
         │
         ├─ Generate RemoteDeviceCredentialDownloadModel
         │  with OTP and download_token
         │
         ├─ Generate QR code URL with token
         │  (qr_code.generate_file_download_qr_url)
         │
         └─ Generate QR code image
            (qr_code.generate_qr_code)
            
┌─────────────────┐
│ User Scans QR   │
└────────┬────────┘
         │
         v
┌─────────────────────────┐
│ QRCodeCredential        │
│ DownloadView            │
│ (qr_download.py)        │
└────────┬────────────────┘
         │
         ├─ Validate token via check_token()
         │
         ├─ Serialize credential in requested format
         │  (PKCS12, PEM_ZIP, PEM_TAR_GZ)
         │
         ├─ Generate FileResponse
         │
         └─ Delete CDM (cleanup)
```

## Security Features

1. **Token-Based Authentication**
   - Tokens are cryptographically random (32 bytes, URL-safe)
   - Single-use tokens (deleted after download)
   - 3-minute expiration time

2. **OTP Protection**
   - 3 failed OTP attempts invalidate session
   - OTP is set to '-' after successful validation

3. **No Password in QR Code**
   - QR code only contains download URL and token
   - Private keys are protected with password during download
   - Password can be optionally included in URL (not recommended)

4. **Automatic Cleanup**
   - Expired tokens are automatically cleaned up
   - Download sessions are deleted after successful download

## Data Required for QR Code

The QR code encodes the following data:

```
https://trustpoint.example.com/devices/credentials/{credential_id}/qr-download?token={download_token}&format={file_format}
```

**Parameters:**
- `credential_id`: ID of the IssuedCredentialModel
- `download_token`: Authentication token (generated by RemoteDeviceCredentialDownloadModel)
- `format`: File format (PKCS12, PEM_ZIP, PEM_TAR_GZ)

**Example QR Code Data:**
```
https://trustpoint.example.com/devices/credentials/123/qr-download?token=abc123def456&format=PKCS12
```

## Installation Requirements

The module requires the `qrcode` library with PIL support:

```bash
uv add "qrcode[pil]"
```

If not installed, the system gracefully degrades:
- QR code section is hidden
- Traditional OTP workflow still works
- No errors are raised

## Usage Example

### For Administrators

1. Go to device credential download page
2. Click "Download on Device browser"
3. Two options are presented:
   - **Option A (QR Code)**: Scan QR code with device camera → Immediate download
   - **Option B (Traditional)**: Copy URL and OTP → Manual entry → Download

### For Developers

```python
from devices.qr_code import generate_qr_code, generate_file_download_qr_url

# Generate download URL
download_url = generate_file_download_qr_url(
    base_url='https://trustpoint.example.com',
    credential_id=123,
    token='secure_token',
    file_format='PKCS12'
)

# Generate QR code as base64 data URL
qr_code_data_url = generate_qr_code(download_url)

# Use in template
context['qr_code_data_url'] = qr_code_data_url
```

## Supported File Formats

### PKCS#12 (.p12, .pfx)
- Single file with private key and certificates
- Password-protected
- **Best for mobile devices and browsers**
- Most widely supported format

### PEM ZIP (.zip)
- Separate files in ZIP archive
- `private_key.pem` (password-protected)
- `certificate.pem`
- `certificate_chain.pem`

### PEM TAR.GZ (.tar.gz)
- Compressed archive with same contents as ZIP
- Better for Unix/Linux systems
- Smaller file size

## Questions Answered

### What data does the QR code contain?

The QR code contains a complete download URL with:
- Base URL of Trustpoint server
- Credential ID
- Authentication token (time-limited, single-use)
- Requested file format

### How secure is it?

Very secure:
- Tokens expire after 3 minutes
- Single-use tokens (deleted after download)
- No password stored in QR code
- Private keys are encrypted with user-provided password

### Can users choose the file format?

Currently, the QR code defaults to PKCS#12 (most widely supported). The URL can be modified to support other formats by changing the `format` parameter in `generate_file_download_qr_url()`.

### What happens if the QR library is not installed?

The system gracefully degrades:
- QR code section is not shown
- Traditional OTP workflow still works
- No errors occur
- `QRCODE_AVAILABLE` flag prevents execution of QR code generation
